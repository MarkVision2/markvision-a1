## Цель

Сделать раздел `/analytics/creatives` («Воронка по креативам») единым источником правды по креативу: цифры бьются с дашбордом и аналитикой, видно и Meta-, и CRM-метрики, есть удобные фильтры/сортировки, превью открывается всегда, по клику — полная карточка креатива с воронкой и списком привязанных лидов/продаж.

## Почему сейчас «не сходится»

Проверил данные в БД:

- В таблице `leads` всего 45 лидов, но `meta_ad_id` есть только у **9** — поэтому на странице «9 лидов». Это и есть «привязанные к креативам». Остальные 36 пришли вручную / без UTM `utm_content={{ad.id}}` / без CTWA referral — их физически нельзя присвоить конкретному креативу.
- `meta_creative_daily` хранит расход/лиды за 30 дней (486109 ₸, 365 лидов), а `cabinet_daily_insights` — только за 19 дней (329523 ₸, 248 лидов). Это разные источники синхронизации (`meta-structure-sync` для креативов и `meta-daily-sync` для кабинетов), и они расходятся → дашборд и «Воронка по креативам» дают разные суммы.
- Дата в `meta_creative_daily.date` приходит из Meta (часовой пояс рекламного аккаунта), а CRM-view `meta_creative_crm_daily` пересчитывает в `Asia/Almaty` — на стыке суток метрики попадают в разные дни.
- На странице по умолчанию включён фильтр «Только с лидами» — пользователь видит ~5 строк, хотя креативов 185.
- Превью в таблице — миниатюра 56×56 без авто-постера видео и без рефреша истёкшей ссылки, поэтому часть карточек пустая.

## Что сделаем (только UI/презентация + один согласующий бэк-апдейт)

### 1. Сходимость цифр

- Перевести `meta_creative_crm_daily` на ту же логику дат, что и `cabinet_daily_insights` (UTC-дата создания/оплаты), чтобы недельные и месячные суммы по креативам совпадали с дашбордом.
- Добавить в `meta_structure_sync` (или ночной cron) допиливание `cabinet_daily_insights` из агрегата `meta_creative_daily` — один источник чисел по расходу/лидам Meta. Дашборд и «Воронка» начнут показывать одинаковые суммы.
- В KPI-полосе наверху «Воронки» добавить две колонки: «Лиды Meta» (из `meta_creative_daily`) и «Лиды CRM» (привязанные через `meta_ad_id`), плюс подсказку «X из Y лидов привязано к креативам — настройте `utm_content={{ad.id}}`, чтобы привязка стала полной».

### 2. Реальные фильтры и сортировки

- Статус: **Все / Активные / На паузе / Архив** (по `effective_status`).
- Тип: **Все / Видео / Картинка / Карусель**.
- Слайдеры/чипы: «есть расход», «есть лиды», «есть продажи», «ROMI > 0».
- Поиск — оставить (по имени и `ad_id`).
- Сортировки: расход, лиды Meta, лиды CRM, продажи, выручка, ROMI, CPL, CTR, имя.
- Чекбокс «Только с лидами» по умолчанию **выключен**, чтобы пользователь видел весь набор.

### 3. Превью, которое всегда работает

- Заменить локальный `CreativeThumb` на общий `CreativePreview` (как в `CreativesGrid`): автокапча постера для видео, fallback на `meta-creative-refresh` при истёкшей ссылке, иконка типа, бейдж статуса.
- Сделать строку таблицы кликабельной: открывает боковую панель `CreativeDetailDrawer`.

### 4. Карточка креатива (новый `CreativeDetailDrawer`)

Открывается по клику на строку. Внутри:

- Большое превью (видео автоплей / картинка) + название, `ad_id`, статус, кампания, адсет.
- 4-шаговая воронка (Лид → Квал → Продажа → Выручка) с числами и конверсиями между шагами — данные из `get_creative_funnel` (RPC уже есть, см. `useCreativeFunnel`).
- Блок «Деньги»: Расход, CPL Meta, CPL CRM, средний чек, Выручка, ROMI, Прибыль.
- Список последних лидов с этого креатива (имя, телефон, стадия, сумма, дата) — клик ведёт в карточку лида в CRM.
- Список оплаченных сделок этого креатива (сумма, дата, метод).
- Кнопка «Открыть в управлении рекламой» — ведёт на `/ads?tab=creatives&ad=<id>`.

### 5. Атрибуция «как лид попал в этот креатив»

- В карточке лида (`LeadAttribution.tsx`) и в новом drawer показывать одинаковый блок: канал привязки (CTWA / UTM `utm_content` / форма Meta), исходный URL/реферрер, ссылка на креатив.
- В drawer добавить мини-инструкцию «как добиться 100% привязки» (UTM-шаблон, CTWA, имена объявлений).

## Технические детали

Файлы, которые изменим:

- `src/pages/CreativeFunnel.tsx` — фильтры, сортировки, дефолты, KPI с двумя колонками лидов, использование общего превью, открытие drawer.
- `src/components/dashboard/CreativesGrid.tsx` — вынесем `CreativePreview` в отдельный файл `src/components/creatives/CreativePreview.tsx`, чтобы переиспользовать.
- `src/components/creatives/CreativeDetailDrawer.tsx` — новый компонент (Sheet из shadcn).
- `src/hooks/useMetaStructure.ts` — расширить `MetaCreativeRow` полем `metaLeads` отдельно от `crmLeads` (уже есть `leads`), фильтр по статусу/типу делаем на клиенте.
- `src/hooks/useCreativeFunnel.ts` — уже есть, добавим вывод среднего чека и CPL/ROMI чтобы drawer не дублировал расчёты.

Миграция БД (`supabase--migration`):

- Пересоздать `meta_creative_crm_daily` с датами в UTC (как у `cabinet_daily_insights`).
- Backfill: `INSERT … ON CONFLICT` в `cabinet_daily_insights` из агрегата `meta_creative_daily` по `(cabinet_id, date)` за последние 90 дней, чтобы убрать рассинхрон.

## Что НЕ делаем

- Не меняем бизнес-логику CRM-воронки и стадий.
- Не трогаем `lead-intake` / `greenapi-webhook` (атрибуция уже работает; недостающие 36 лидов без `meta_ad_id` — это лиды без рекламной метки, их не существует «в креативе»).
- Не вводим новые провайдеры рекламы.

## Подтверждение после реализации

- Сумма расхода и лидов Meta за выбранный период в «Воронке» = сумме на `/dashboard` и `/analytics`.
- В drawer-карточке цифры воронки = тому, что отдаёт RPC `get_creative_funnel`.
- Каждый видео-креатив показывает постер; если ссылка протухла — авто-рефреш.
- Фильтры «Активные / по расходу / по выручке» меняют выдачу и пересчитывают KPI-полосу.
