# Этап 3. Критик отбора

**Исполнитель:** сильная модель, чистый контекст, роль по `critic.md`. **Вход:** `trends.json`,
`candidates.json`, правила этапа 2, `project.md`, `antipatterns.md`. **Выход:** `approved.json`
(тот же формат, что `candidates.json`, только `selected: true`), записи в `critic.log`.

## Что проверять по каждому элементу
1. **Согласованность критериев.** Возьми все `rejected_reason` и сгруппируй. Если одна причина
   применена к одним и не применена к другим с тем же признаком — это `inconsistent_criteria`.
   Исправь: либо верни отсеянных, либо отсей пропущенных, по правилу этапа 2.
2. **Занижение объёма.** Если `selected` меньше трети от постов с рабочей мыслью — пройди
   отсеянные заново. `underdelivered`.
3. **Метка формата.** `format_ok=false` с причиной «есть скринкаст» без попытки найти фрагмент —
   `format_mislabel`. Найди фрагмент сам или подтверди, что мысли без экрана нет.
4. **Соответствие проекту.** `why_fits` ссылается на реальную боль/сегмент из `project.md`, а не
   на общее «полезно всем».
5. **Дубли.** Два кандидата с одной сутью → один `topic_key`; если суть буквально одинаковая —
   оставить один (тот, где `source_facts` богаче). `duplicate_topic`.
6. **`source_facts`** — только дословное из источника. Всё, чего в транскрипте/подписи нет,
   убрать.

## Эскалация (только это)
- Тема на грани позиционирования проекта (например, спорная практика в нише) — вопрос
  человеку с вариантами «берём / не берём».

## Выход
- `approved.json` — итоговый список, количество динамическое.
- `critic.log` — каждая находка. Системные (≥ 2 повторов) → правило в `antipatterns.md`.
