# Подключение сети Instagram-аккаунтов (instagram-connect)

Оркестратор этапов 2–6 ТЗ `docs/TZ-instagram-100-accounts.md`. Читать ТЗ первым: раздел 3
(«факты, добытые проверкой») экономит день — там всё, что уже проверено и перепроверять не надо.
Здесь — только порядок действий, точные вызовы и ворота.

Два инструмента:
- **MCP `phonegrid`** (зарегистрирован в `~/.claude.json` на Mac) — профили браузера:
  `manage_browser` (create / start / close), `browser_operate` (navigate, click, fill, act,
  observe, extract, get_text, screenshot). Один вызов = одно действие.
- **`node scripts/instagram-connect.mjs`** — всё, что идёт через наш backend с ключом
  автоматизации (`AUTOMATION_KEY` в `.env` = `automation_settings.cron_secret`): ссылки пачкой,
  приёмка этапов, реестр IP, пресет, проверка токенов, трасса публикации, TOTP.
  Реестр пачки — `work/ig-connect/<batch>.json` (в git не попадает).

## Принципы (не нарушать)
1. **Пароли и TOTP-секреты не хранятся нигде в проекте** — ни в реестре, ни в `.env`, ни в чате
   дольше, чем нужно для одного `fill`. Источник — менеджер паролей заказчика; TOTP считается
   командой `totp` (секрет со stdin).
2. **Пачками по 20–30.** После пачки — сутки наблюдения за дайджестом ошибок, потом следующая.
3. **Один профиль = один аккаунт = свой адрес выхода.** Совпадений IP между профилями быть не
   должно — команда `ip` это проверяет по всем пачкам.
4. **Платные и внешние действия — только по явной команде пользователя:** создание профилей
   (`manage_browser create`), первый вход по паролю, выдача ссылок. Сообщить, что будет сделано,
   и получить «да».
5. **Первый вход — с паузами.** Между входами в разные аккаунты 3–10 минут, не пачкой. Три
   блокировки подряд — стоп и разбор, а не четвёртая попытка.
6. **Ничего не чинить руками в базе.** Все правки аккаунтов — через `preset` / интерфейс.

## Предпосылки (этапы 0–1 ТЗ, делает заказчик)
Перед стартом спросить и зафиксировать в чате:
- App Review Meta пройден, приложение **Live**, права `instagram_business_basic` +
  `instagram_business_content_publish` выданы. Пока нет — подключаются только аккаунты с ролью
  в приложении (тестовая пятёрка), и это надо сказать прямо.
- Список аккаунтов пачки: @хэндл, страна/город, тип (Business/Creator подтверждён), какой прокси.
- Прокси на каждый профиль (липкая сессия, страна аккаунта), в формате
  `scheme://логин:пароль@хост:порт`.
- `project_id` проекта в MarkVision и `AUTOMATION_KEY` в `.env`.
- Открытые вопросы ТЗ (раздел 7): бюджет на прокси, свои аккаунты или клиентские, статус App Review.

## Этап 2. Профили с прокси и вход

### 2.1 Создать профили
`manage_browser action=create` — до 200 за вызов, но делать по размеру пачки. На профиль:
- `envName` = `@хэндл` (только так — при сотне штук иначе перепутать);
- `proxy`: `proxyProvider` по схеме (http / https / socks5 / ssh либо интеграция провайдера),
  `proxyIp`, `proxyPort`, `username`, `password` — свой на профиль;
- `operatorSystemId`: 3 Android / 4 iOS для аккаунтов, которые вели с телефона, 1 Windows /
  2 macOS — для остальных; `browserTypeId` 1 Chrome; `browserCore` 0 (автоподбор).

Записать `envId` каждого профиля в реестр — после `links` (2.4) командой
`ip --batch <batch> --profile @хэндл=<envId>`; до этого держать таблицу «хэндл → envId» в чате.

### 2.2 Проверить адрес выхода — ДО входа
```
manage_browser action=start envName=@хэндл
browser_operate action=navigate url=https://api.ipify.org?format=json
browser_operate action=get_text
```
Адрес должен быть страны аккаунта и не совпадать ни с одним из уже записанных. Если выход
не через прокси (адрес Mac) — профиль не трогать, чинить прокси.

### 2.3 Прогреть и войти
1. `navigate https://www.instagram.com/` → 1–3 минуты «полистать»: `act "scroll the feed
   slowly a few screens"` два-три раза с паузами.
2. Вход через `act` (вёрстка Instagram меняется, жёсткие селекторы — только запасной путь):
   - `act "click the Log in link"` (если открылся лендинг);
   - `act "type <логин> into the username field"`;
   - `act "type <пароль> into the password field"` — пароль берётся из менеджера паролей на этот
     один вызов;
   - `act "click the Log in button"`.
   Запасной путь CSS: `fill input[name="username"]`, `fill input[name="password"]`,
   `click button[type="submit"]`.
3. Двухфакторка: `echo "$TOTP_SECRET" | node scripts/instagram-connect.mjs totp` → `code` →
   `act "type <code> into the security code field and submit"`. Код живёт 30 с — смотреть на
   `seconds_left`, при < 8 брать `next`.
4. `observe` / `screenshot` — что показал Instagram:
   - лента → вход есть; `act "click Not now"` на «Сохранить данные входа?» и «Включить
     уведомления?» — сохранять вход как раз нужно, поэтому на первом лучше `act "click Save info"`;
   - «Подтвердите, что это вы» / «Мы заметили необычный вход» → подтверждать «Это был я» с
     телефона, где аккаунт уже залогинен; профиль оставить открытым, повторить `observe`;
   - «Мы заблокировали попытку входа» → закрыть профиль, отметить аккаунт в чате как
     «заблокирован вход», к следующему; после трёх подряд — стоп (принцип 5). Резерв для таких —
     облачный телефон (ТЗ, этап 2, резервный маршрут).
5. Проверить, что сессия живёт: `manage_browser close` → `start` → `navigate
   https://www.instagram.com/` → лента без формы входа. Только после этого профиль считается
   готовым.

### 2.4 Реестр и приёмка этапа
Выдать ссылки (это и создаёт реестр пачки — см. 3.1), затем записать адреса и профили:
```
node scripts/instagram-connect.mjs ip --batch <batch> --set @a=93.157.181.157 --profile @a=<envId> --set @b=… --profile @b=…
```
или из файла `--import ips.csv` (`хэндл;ip;envId`). Команда печатает «профиль → @хэндл → IP»,
ищет повторы адресов по всем пачкам и даёт код выхода 0 только при приёмке этапа 2.

## Этап 3. Конвейер подключения

### 3.1 Ссылки
```
node scripts/instagram-connect.mjs links --project <uuid> --handles @a,@b,@c --batch <batch> --hours 48 [--group <id>] [--persona <id>]
```
Одноразовая ссылка на аккаунт (`max_uses 1`, `platforms ["instagram"]`, `label @хэндл`).
Реестр — `work/ig-connect/<batch>.json`. Повторный запуск не выдаёт вторую ссылку тому, у кого
она уже есть (`--renew` — выдать заново, если старая сгорела).

### 3.2 В каждом профиле — одно согласие
```
manage_browser action=start envName=@хэндл
browser_operate action=navigate url=<url из реестра>
browser_operate action=act instruction="click the button «Подключить аккаунт Instagram»"
```
Кнопок у Instagram на странице две — нужна **«Подключить аккаунт Instagram»** (вход логином
Instagram), не «через Facebook». Запасной путь: `click` по первой кнопке с текстом
`Подключить аккаунт Instagram`. Страница уведёт на `instagram.com/oauth/authorize…`; при живой
сессии Instagram показывает только экран согласия:
```
browser_operate action=observe   # убедиться, что это экран согласия, а не форма входа
browser_operate action=act instruction="click the Allow button"   # «Разрешить»
```
Если вместо согласия — форма входа, сессия не сохранилась: вернуться в 2.3, ссылку не тратить
(она сгорает только после успешного возврата).

Возврат на `/connect/<token>?publish_connected=instagram&account=…` — страница покажет
«Успешно подключено»:
```
browser_operate action=get_text   # ждать текст «Успешно подключено»; ошибка — текст под «Ссылка не работает» / красная карточка
manage_browser action=close envName=@хэндл
```
Ошибку с площадки (`publish_error`) переписать в чат дословно и идти к следующему профилю.
Между профилями пауза 1–3 минуты.

### 3.3 Приёмка и пресет
```
node scripts/instagram-connect.mjs status --batch <batch>
```
По каждому хэндлу: ссылка использована, аккаунт в сетке, `auth_status = connected`, в
`oauth_scope` есть `instagram_business_content_publish`, `connection_type = oauth`. Код выхода 0 —
этап 3 принят. Незакрытые ссылки у подключённых — отозвать (`connect_link_revoke` в интерфейсе
«Ссылки»); сгоревшие без аккаунта — `links … --renew`.

Настройки на всю пачку одной командой (те же поля, что пресет в интерфейсе):
```
node scripts/instagram-connect.mjs preset --batch <batch> --group <id> --persona <id> --timezone Asia/Almaty --window 10:00-20:00 --daily-limit 1 --ramp --enable
```
Новый аккаунт стартует с разгона (`--ramp`) и лимита 1 в день — ТЗ, раздел про планировщик.

## Этап 4. Продление токенов — проверить на первых 3–5 аккаунтах
Токен IGAA… живёт 60 дней. Пока аккаунтов мало:
```
node scripts/instagram-connect.mjs tokens --batch <batch>          # или --project <uuid> --account <id>…
```
Это `publish-monitor mode=tokens` только по выбранным аккаунтам. В отчёте по каждому: вид
токена, продлён ли и почему нет (свежему токену меньше 24 ч — площадка не даст, это норма),
новый `token_expires_at`, `token_refreshed_at`, живость, `auth_status`. Ошибки продления не
глотаются: попадают в отчёт и в `last_error` аккаунта (`автопродление: …`).

Проверка на протухшем токене: в интерфейсе у тестового аккаунта «Отключить», затем в
Instagram — «Приложения и сайты → удалить MarkVision», снова подключить и отозвать доступ на
стороне Instagram; после `tokens` аккаунт обязан получить `auth_status reconnect_required`,
`status token_expired`, уведомление в центре уведомлений и строку «Требуют внимания» в
ближайшем дайджесте. Команда даёт код 0, если мёртвые помечены правильно и ошибок продления нет.

## Этап 5. Живой прогон
1. Ролик в «Видео» (или из цеха — `publish_videos` через `_lib/publishLibrary.ts`), раскладка
   по группе пачки.
2. Дождаться воркера (кроны `publish-worker-p*` каждую минуту), затем:
```
node scripts/instagram-connect.mjs trace --project <uuid> --video <id>     # или --job <id>
```
Трасса `queued → processing → published`, `external_post_id`, ссылка на пост — проверить глазами,
что пост виден в аккаунте. Через сутки повторить `trace`: должна появиться точка `d1` в
`post_metrics`; код 0 — этап 5 принят. Цифры — в «AI Content Analyst».

## Этап 6. Масштабирование
Повторять этапы 2–3 пачками по 20–30 (`--batch` с новым именем), после каждой — сутки на дайджест.
`ip` всегда проверяет адреса по всем пачкам сразу.

## Резервный маршрут — облачный телефон
Аккаунт наглухо не пускает в браузер → раздел «Устройства» (`account-devices`, `docs/PHONEGRID.md`):
ссылку на телефоне перехватывает приложение Instagram, пароль не спрашивают, одно нажатие
руками в окне телефона. Для сотни не годится, для единичных случаев — работает.

## Что отдать пользователю в конце пачки
- реестр `work/ig-connect/<batch>.json` и вывод `status` (принято / что не так по хэндлам);
- таблица «профиль → @хэндл → IP» из `ip`;
- список аккаунтов, которые не вошли (блокировка входа) — с предложением резервного маршрута;
- отчёт `tokens` на первой пачке — до начала второй.
