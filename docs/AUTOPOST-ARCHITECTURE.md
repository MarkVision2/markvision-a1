# Автопостинг: полный путь видео и что где живёт

Документ отвечает на три вопроса: **как система работает без включённого компьютера**,
**где место PhoneGrid и Multilogin**, и **что происходит с видео от файла до отчёта**.

Детали реализации — `docs/PUBLISHING-SYSTEM.md` и `docs/AUTOPOSTING-PLATFORM.md`,
контракт внешнего API — `docs/PUBLIC-API.md`, облачные телефоны — `docs/PHONEGRID.md`.

## 1. Главное правило: два разных контура

Их постоянно путают, поэтому здесь прямо:

| | Публикация | Прогрев и заведение аккаунтов |
|---|---|---|
| Чем делается | официальные API площадок | облачные телефоны PhoneGrid (RPA) |
| Где выполняется | Supabase edge + pg_cron | серверы PhoneGrid |
| Нужен ли компьютер | нет | нет (через Open API) |
| Как часто | по расписанию слотов | ежедневно, 15 дней на аккаунт |

**Публиковать с телефона не нужно.** Это медленно, ломается от смены вёрстки приложения
и не отдаёт статистику. Телефон нужен ровно там, где API бессилен: создать аккаунт,
прогреть его, перевести в Business, пройти проверку личности.

## 2. Компьютер не нужен — где что крутится

              ЧТО ТРЕБУЕТ ВАШ MAC (редкие ручные операции)
     • PhoneGrid Local API (127.0.0.1:30000) — только удобство разработки
     • Multilogin — ручная поддержка аккаунтов
     • Первый вход в аккаунт, SMS-подтверждение, восстановление доступа

**Вывод:** ежедневная работа идёт целиком на серверах. Mac нужен эпизодически —
когда заводите новый аккаунт или чините сломавшийся.

Важная деталь: у PhoneGrid **два** API. Local API работает только при запущенном клиенте
на этой машине, Open API (`api.phonegrid.com`, OAuth client_credentials) — откуда угодно,
и он умеет то же самое, включая RPA-расписания. **Для серверной автоматизации используем
только Open API.** Local API остаётся для отладки с ноутбука.

## 3. Место Multilogin

Multilogin — антидетект-браузер, он в этой схеме **не публикует**. Его роль — ручные
операции, где нужен браузер с сохранённым отпечатком:

- зайти в Meta Business, привязать Instagram к Facebook-странице;
- пройти OAuth площадки при подключении аккаунта в MarkVision;
- разобраться с блокировкой, сменить пароль, ответить на проверку;
- посмотреть аккаунт глазами, когда что-то пошло не так.

Мобильные приложения (регистрация, прогрев) — это PhoneGrid, там настоящий Android.
Веб-кабинеты (Meta Business, OAuth) — это Multilogin. Они не конкурируют, а делят зоны.

## 4. Путь аккаунта: разово, 15 дней

Прежде чем аккаунт начнёт публиковать, он проходит один раз:

1. **Регистрация** — облачный телефон PhoneGrid, свой мобильный прокси. Вручную:
   ввод пароля и SMS-кода автоматизировать нельзя и не нужно.
2. **Прогрев, 15 дней** — RPA-задача каждый день, нарастающая активность
   (дни 1–2 только просмотр, 3–4 первые лайки, 5–7 подписки, 8–14 обычная активность).
   Ставится расписанием в PhoneGrid, крутится на их серверах:
   `node scripts/phonegrid.mjs warmup <phoneId> ig <день>` или `rpa/task/save` с `scheduleType: DAILY`.
3. **Business/Creator + Facebook-страница** — в приложении и Meta Business (Multilogin).
4. **Подключение в MarkVision** — OAuth в разделе «Публикации» → аккаунт появляется
   в `publish_accounts` со статусом `active`.
5. **Телефон выключается.** Дальше аккаунт живёт в API-контуре, устройство ему не нужно:
   публикация через официальный API не привязана к IP и не считается сменой устройства.

Новый аккаунт система разгоняет сама: `publish_account_effective_limit` даёт
1 публикацию в день первую неделю, потом 2, потом 3, потом штатный `daily_limit`.

## 5. Путь видео: ежедневно

### Шаг 1. Видео появляется

Три источника, все ведут в одну точку:

- **Google Drive** — n8n следит за папкой, находит новый файл, скачивает;
- **Контент-завод MarkVision** — ролик готов в разделе «AI монтаж → Готовые»;
- **Внешний клиент** — по публичному API с ключом проекта.

### Шаг 2. Видео попадает в MarkVision

Единая точка входа — публичный API (`docs/PUBLIC-API.md`):

```bash
# 1. получить ссылку на загрузку
curl -X POST "$API/media/upload-url" -H "Authorization: Bearer $KEY" \
  -H "Content-Type: application/json" -d '{"filename":"reel.mp4"}'
# 2. залить файл по выданной ссылке (PUT)
# 3. создать публикацию с целью
curl -X POST "$API/publications" -H "Authorization: Bearer $KEY" \
  -H "Content-Type: application/json" -d '{
    "file_url": "…",
    "caption": "текст поста",
    "target": { "group_id": "…" }
  }'
```

`target` — это и есть ответ на «опубликовать во все инстаграмы»: указываете **группу
аккаунтов**, а не каждый аккаунт руками. Один ролик на всю сеть — `POST /publications/distribute`
(раскладка «один ролик → один аккаунт», чтобы одинаковое видео не выходило дважды с одного профиля).

То же самое доступно как MCP-инструменты: `markvision_upload_media`, `markvision_create_publication`,
`markvision_distribute` — то есть заявку может поставить и Claude-сессия.

### Шаг 3. Система сама расставляет время

`plan_publish_slots()` для каждого аккаунта считает слот:

- **окно публикаций** аккаунта в его часовом поясе (например 9:00–21:00);
- **минимальный интервал** от предыдущей публикации;
- **дневной лимит** с учётом разгона новых аккаунтов;
- **джиттер** — сдвиг на случайные минуты, чтобы посты не выходили секунда в секунду;
- **темп группы** `per_hour` — сколько аккаунтов в час.

Это важнее, чем «крон в 9:00 публикует всё разом»: одновременная публикация одного ролика
с двадцати аккаунтов — самый заметный признак сетки.

### Шаг 4. Публикация

`pg_cron` раз в минуту забирает созревшие задания (`claim_publish_jobs`), воркер публикует
через официальный API площадки и пишет результат: `external_post_id`, `external_post_url`,
`published_at`. Ошибки не теряются: временные уходят в `retry` с новой попыткой,
постоянные — в `failed` или `manual_review` с причиной.

### Шаг 5. Отчёт и статистика

- **Сразу после публикации** — запись в журнал, уведомление в Telegram проекта.
- **Через 1, 3 и 7 дней** — `publish-metrics` собирает статистику площадки в `post_metrics`:
  просмотры, охват, лайки, комментарии, репосты.
- **Часовой дайджест** — `publish-monitor` шлёт сводку: сколько опубликовано, что упало.
- **Страница «Публикации»** — статусы по аккаунтам, по видео, здоровье токенов (`health_score`),
  метрики. Аварийная пауза проекта — один рубильник, очередь при этом сохраняется.

## 6. Что уже работает, а чего не хватает

| Кусок | Состояние |
|---|---|
| Телефон и прогрев в карточке аккаунта (без кабинета PhoneGrid) | **работает** — «Устройство и прогрев» в меню аккаунта |
| Публичный API, MCP, ключи проекта | **работает** |
| Очередь, слоты, разгон, лимиты, джиттер | **работает** |
| Instagram — публикация | **работает**, проверено на живом ролике |
| TikTok, YouTube, Threads — публикация | код есть, нужен App Review / OAuth-клиент |
| Метрики d1/d3/d7, дайджест, здоровье | **работает** |
| PhoneGrid: телефоны, прокси, ADB, RPA-прогрев Instagram | **работает** |
| RPA-прогрев TikTok | нужна требуемая версия приложения из UI маркетплейса |
| Забор видео из Google Drive | **не сделано** — нужен воркфлоу n8n |
| Ежедневное расписание прогрева через Open API | **не сделано** — разовые задачи работают |

## 7. Порядок запуска

1. Подключить в MarkVision те аккаунты, что уже есть, и проверить публикацию ролика — готово.
2. Сделать воркфлоу n8n: папка Google Drive → `POST /media/upload-url` → `POST /publications`.
3. Завести сеть: телефон → регистрация → 15 дней прогрева → OAuth → аккаунт в группе.
4. Перевести прогрев на ежедневные расписания PhoneGrid Open API, чтобы не трогать вручную.
5. Пройти App Review TikTok (`docs/TIKTOK-DEVELOPER-APP.md`) и подключить YouTube.
