# Монтаж съёмки: как связаны сайт (Контент-завод) и скилы montage-pipeline

## Картина целиком

```
САЙТ (Контент-завод → Видео → «Монтаж съёмки», /create/montage-lab)
  │  пользователь: загружает видео «говорящей головы», выбирает форматы
  │  (16:9 / шортсы), пишет пожелания, включает доставку в Telegram
  ▼
Supabase (szfgdruhlebfvcmlvxdk)
  • bucket montage-uploads  ← исходник
  • таблица montage_jobs    ← заявка (status: queued)
  ▼
CLAUDE-ВОРКЕР (сессия Claude Code в этом репозитории)
  «разбери очередь монтажа» →
  1) node scripts/montage-worker.mjs next          — забрал заявку, скачал исходник в work/<jobId>/
  2) скилы делают монтаж (см. ниже)                — прогресс виден на сайте (…status <jobId> "…")
  3) node scripts/montage-worker.mjs complete …    — залил рендеры и закрыл заявку
  ▼
edge-функция montage-worker (service role)
  • рендеры → bucket renders
  • строки в heygen_usage (source montage-pipeline)  → раздел «AI монтаж → Готовые»
  • если у проекта привязан Telegram (telegram_links) → бот присылает видео в чат
```

Важно понимать: **монтаж исполняет не сервер, а Claude-сессия в этом репозитории**
(пайплайну нужны Python, FFmpeg, Remotion и разметка Клодом). Сайт — это витрина и очередь;
Claude — монтажёр, который очередь разбирает. Пока сессию не запустили и не сказали
«разбери очередь монтажа», заявки висят в статусе «В очереди».

## Кто из скилов что делает

| Скил | Роль в конвейере |
|---|---|
| `montage-pipeline` | Оркестратор: стадии, ворота, режим очереди Контент-завода |
| `brand-intake` | Разовый онбординг бренда → `brand.config.json` (шрифты, эффекты, темп) — влияет на все следующие монтажи |
| `script-gen` | До съёмки: сценарий в голосе автора (`work/<id>/script.md`); для заявок с сайта обычно не нужен — видео уже снято |
| `broll-gen` | Вставки: промты → генерация картинок → `public/inserts/<id>/` (по маркерам сценария или транскрипту) |
| `remotion` | Справочник правил Remotion — используется при любой работе с композициями |
| `publish-pack` | После рендера: описание YouTube, теги, ТГ-пост из транскрипта → `work/<id>/publish.md` |

## Что происходит внутри монтажа (Stage 1 → 4 скилла)

1. Прокси исходника (all-intra H.264) → `remotion/public/`.
2. Deepgram-транскрипт (`DEEPGRAM_API_KEY` из `.env`) → `words.json`.
3. Очередь сайта: исходник **всегда цельный** (`delete.json` = `{"delete":[],"keep_full":true}` —
   без jump-cut). Полный **16:9 обязателен**; шортсы — только опциональная доп. нарезка.
   Claude → `accents.json` + **motion-вставки** (`inserts.json`). `brief` + `broll_mode` — вход разметки.
4. `edl.py` → монтажный лист; `faces.py` → позиция лица (зумы/кроп).
5. `props.py` + `audio.py` → пропсы Remotion + declick-дорожка голоса.
6. Шортсы (если заказаны): отбор моментов → `shorts.json` → карaоке-субтитры 9:16.
7. Рендер Main169 / Short-* → `out/*.mp4`.

## Режимы ворот

- **Заявка с сайта** = явная команда «смонтируй и отрендери» → Claude проходит стадии сам,
  без промежуточных подтверждений в чате; прогресс пишется в заявку (`status`), результат —
  `complete` (публикация + Telegram) или `fail` (причина видна на сайте и в TG).
- **Монтаж из чата** («смонтируй видео из …») → классические ворота скилла: REVIEW.md,
  брак картинок, финальный рендер только по явной команде; публикация —
  `scripts/montage-publish.mjs`.

## Доставка результата

- **Всегда**: раздел «AI монтаж → Готовые» у проекта-клиента (страница `/create/montage`,
  вкладка «Готовые») — там же, где видео HeyGen. Плюс статус «Готово» со ссылками на
  скачивание прямо в «Монтаж съёмки».
- **Telegram** (если включён тумблер в заявке): бот присылает готовый ролик и шортсы в чат,
  привязанный к проекту. Привязка — кнопка «Подключить Telegram» на странице «Монтаж съёмки»
  (та же, что для HeyGen: бот получает `/link КОД`).

## Инфраструктура (всё уже создано и задеплоено)

- `montage_jobs`, `montage_settings` — таблицы в Supabase szfg (миграция
  `supabase/migrations/20260715160000_montage_jobs.sql`, применена).
- bucket `montage-uploads` (исходники, public), рендеры — в существующий bucket `renders`.
- edge-функция `montage-worker` (задеплоена, `verify_jwt=false`, auth по заголовку
  `x-montage-key` = `montage_settings.worker_key` = `MONTAGE_WORKER_KEY` в `.env`).
- Telegram: используется существующий бот (`TELEGRAM_BOT_TOKEN` в секретах edge-функций)
  и таблица `telegram_links` — отдельной настройки не нужно.

## Масштабирование (как это работает без команд в чате)

- **Атомарная очередь.** Забор заявки — RPC `claim_montage_job()` (`FOR UPDATE SKIP LOCKED`):
  сколько угодно параллельных воркеров, одна заявка достаётся ровно одному. Заявки, зависшие
  в processing/rendering дольше 3 часов (воркер умер), автоматически возвращаются в очередь.
- **Воркер разворачивается одной командой** — `bash scripts/montage-setup.sh` (идемпотентно):
  проверяет ключи и сеть, ставит ffmpeg (статическая сборка, если нет системного), `.venv`
  с зависимостями пайплайна и `npm ci` в remotion/. Работает и в свежей облачной сессии,
  и на любой новой машине.
- **Routine «Монтаж-конвейер: разбор очереди»** (`trig_017trEn3DhvZmonoH1fSfWeU`): каждый час
  поднимает свежую Claude-сессию в облачном окружении, та выполняет setup → `next` → монтаж →
  `complete`, пока очередь не опустеет, и шлёт push-уведомление об итогах.
- **Ключи** воркер берёт из env-переменных окружения (или локального `.env`, который в git
  не попадает): `DEEPGRAM_API_KEY`, `MONTAGE_WORKER_KEY`.
- **Мультиарендность** уже встроена: заявки привязаны к `project_id`, RLS отделяет проекты
  друг от друга, Telegram-доставка — по привязке чата конкретного проекта. Новые клиенты
  ничего не настраивают: проект в приложении + (опционально) `/link` боту.
