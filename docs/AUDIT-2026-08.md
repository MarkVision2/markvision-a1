# Аудит кода MarkVision — август 2026

Проверены: главная и все разделы фронта, CRM и сквозная аналитика, WhatsApp
(Green API + WA Web), реклама Meta и запуск кампаний, Контент-завод и
публикация, все 87 edge-функций, RLS-политики и доступы команды.

Отправная точка: `npm run ci` (lint + typecheck + 433 теста + build) был
**зелёным**. Все дефекты ниже typecheck и тесты не ловили — ошибки PostgREST
и провалы авторизации молча проглатывались (`const { data } = ...` без чтения
`error`), а edge-функции вообще не входят в tsconfig.

## Как искали

1. Прогон `lint` / `typecheck` / `vitest` / `build`.
2. Скрипт сверки всех запросов (`.from().select()`) со схемой БД — ищет
   обращения к несуществующим таблицам и колонкам (молчаливые 400).
3. Скрипт «проигрывания» всех миграций по порядку с учётом
   `CREATE POLICY` / `DROP POLICY` — чтобы получить **итоговое** состояние RLS,
   а не то, что написано в отдельно взятом файле.
4. Чтение критичных путей: авторизация, деньги, публикация, вебхуки.

### Доступы команды — итог проверки

Проверено отдельно, как просили. Итоговое состояние **корректное**:

- `user_can_access_project` = админ **ИЛИ** владелец проекта **ИЛИ** строка в
  `project_members` **именно по этому проекту**. Опасная промежуточная версия
  (доступ ко всем проектам при наличии любой строки в `team_member_modules`)
  была исправлена миграцией `20260521120000`.
- `user_roles` пишет только админ — самоповышение до админа невозможно.
- `project_members` пишет только админ или владелец проекта.
- `leads` и `communications` скоупятся по проекту корректно.

Исправлены перекосы: `events`, `tasks`, `communications` (см. S4 и F7).

## Осталось сделать (требует доступа к БД / решения владельца)

1. **`supabase/migrations_client_config/004_full_schema.sql:186`** —
   `disable row level security` на `clients_secrets` (там `fb_token`,
   `wa_api_token`), `clients_config`, `leads_crm` (телефоны, IP, fbclid),
   `wa_clicks`. При выключенном RLS PostgREST полагается только на GRANT'ы,
   а Supabase по умолчанию выдаёт `anon` полный доступ. Если этот проект ещё
   развёрнут и его ключ где-то публикуется — данные и токены открыты.
   Комментарий в файле («фронт пишет только через service_role-эквивалент»)
   не соответствует коду: `src/integrations/clientConfig/client.ts` ходит туда
   публикуемым ключом из браузера. **Нужно включить RLS и закрыть доступ
   роли `anon`.**
2. **`src/integrations/supabase/types.ts` сильно устарел** — 68 таблиц против
   реальной схемы, нет `stage_role`, `tags`, `temperature`, `media_url` и
   десятков других колонок. Из-за этого по коду расставлены `as any`, которые
   отключают typecheck ровно там, где он нужнее всего. Перегенерировать:
   `supabase gen types typescript --project-id szfgdruhlebfvcmlvxdk`.
3. **`return_url` в OAuth-старте (Meta и Google) не проверяется по белому
   списку** — открытый редирект. Секретов в редиректе нет, приоритет низкий.
4. **`lead-intake` — публичная форма без rate-limit.** Стоит добавить лимит
   по IP/токену, иначе CRM можно засыпать мусорными лидами.
5. **`pipelines_select_scoped` разрешает `project_id IS NULL` всем
   авторизованным** — легаси-воронки видны всем проектам.
6. **`broadcast_sender_daily` считает день по UTC** (`toISOString().slice(0,10)`),
   хотя у кампании есть таймзона: дневной лимит рассылки сбрасывается в
   полночь UTC, а не в полночь проекта.
