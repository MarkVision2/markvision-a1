# SEO MarkVision — как устроено и что делать дальше

## Главное, что нужно понимать про этот сайт

`markvision.kz` — это SaaS за логином. `RequireAuth` редиректит анонимного
посетителя (и робота Google) с `/` на `/login`. Публичного контента на главной
**нет**. Единственная страница с реальным содержимым, которую можно
ранжировать, — `/lab` (лендинг практикума AI Marketing Lab).

Из этого следует прямой вывод: никакая работа с метатегами не заставит сайт
ранжироваться, пока нет публичных страниц с текстом. Метатеги решают, **как**
страница выглядит в выдаче; ранжирует Google **контент**. Что для этого нужно —
в разделе «Что даст рост» ниже.

## Что уже сделано

### Один реестр вместо разрозненных тегов

`src/lib/seo.ts` — единственный источник правды: путь → заголовок, описание,
ключевые запросы, индексировать или нет, приоритет в sitemap, JSON-LD.
Из него берут данные и рантайм, и сборка. Разъехаться они не могут.

### Метатеги на каждой странице (было: одни и те же на всех)

`src/components/seo/SeoManager.tsx` подключён в `App.tsx` и на каждый переход
проставляет `title`, `description`, `canonical`, `robots`, Open Graph, Twitter
Card и JSON-LD. До этого SPA отдавала всем 30+ маршрутам заголовок и описание
главной.

### Статический HTML для индексируемых страниц

`scripts/generate-seo.mjs` после сборки создаёт `dist/lab/index.html` и
`dist/index.html` с уже подставленными метатегами. Это важно, потому что
краулеры соцсетей (Facebook, WhatsApp, Telegram, Twitter) **не исполняют JS** —
без этого шага ссылка на практикум в мессенджере показывала бы карточку
главной. Vercel отдаёт существующий файл раньше SPA-rewrite, поэтому подхват
автоматический.

### Приватные разделы закрыты от индексации

Отдельная заглушка `dist/app.html` с `noindex, nofollow` в сыром HTML — на неё
`vercel.json` отправляет все маршруты, для которых нет статического файла.
Раньше эту роль играл `dist/index.html`, то есть сырой HTML любого приватного
адреса — включая **отчёт клиента по секретной токен-ссылке** — содержал
`robots: index`.

`robots.txt` дополнительно закрывает `/client/`, `/crm`, `/settings`,
`/create/`, `/projects/` и остальные разделы кабинета.

### Исправленные ошибки

| Было | Стало |
|---|---|
| `robots.txt` указывал sitemap на `markvision-a1.lovable.app` — чужой домен, Google такой sitemap игнорирует | `https://www.markvision.kz/sitemap.xml` |
| `sitemap.xml` содержал URL превью-домена Lovable — прямой риск дублей в индексе | Боевые URL |
| `/lab` вообще не было в sitemap | Есть, приоритет 0.9 |
| `/login` был в sitemap | Убран (страница входа не должна занимать место в индексе) |
| Один `title`/`description` на все страницы | Свои у каждой |

### Автоматизация

- `npm run build` сам генерирует `robots.txt`, `sitemap.xml`, `llms.txt`,
  `app.html` и статические страницы. Забыть обновить sitemap физически нельзя.
- `npm run seo` — перегенерация без пересборки.
- `src/test/seo.test.ts` (22 проверки) падает, если: появился маршрут без
  SEO-описания; в реестре остался удалённый маршрут; `title` длиннее 65
  символов; `description` вне 80–170; заголовки дублируются; приватный раздел
  открыт для индексации; домен вернулся на `lovable.app`.
  Проверка встроена в `npm run ci`.

## Карта ключевых запросов

**Честная оговорка:** частотности здесь нет и быть не может — у меня нет
доступа к Яндекс.Wordstat и Google Keyword Planner. Ниже — смысловая карта,
собранная из позиционирования продукта и лендинга. Перед тем как писать
страницы, прогоните её через Wordstat (регион Казахстан) и уберите то, что
имеет нулевую частотность.

### Кластер 1. Практикум и обучение — под `/lab`

Коммерческий intent, самый близкий к текущему контенту.

- практикум по AI маркетингу
- нейросети для маркетолога / для таргетолога
- автоматизация работы таргетолога
- обучение AI маркетингу
- как маркетологу зарабатывать больше
- AI Marketing Lab

### Кластер 2. Продукт — под будущую публичную главную

- автоматизация маркетинга
- сквозная аналитика (+ «сквозная аналитика для малого бизнеса»)
- CRM для маркетингового агентства
- платформа для таргетолога
- отчёты по рекламе для клиента

### Кластер 3. Интеграции — под отдельные посадочные

Каждый пункт — отдельная страница, иначе они конкурируют между собой:

- CRM с WhatsApp / интеграция WhatsApp с CRM
- сквозная аналитика Facebook Ads
- автопостинг в Instagram
- генерация креативов нейросетью
- Meta Conversions API настройка

### Кластер 4. Информационные — под блог

Дешёвый трафик, прогрев к продукту:

- как настроить сквозную аналитику
- что такое CTWA / клик в WhatsApp
- как считать ROAS
- как автоматизировать отчёты по рекламе

## Что даст рост (в порядке отдачи)

1. **Публичная главная.** Сейчас `/` — это редирект на логин. Нужна страница
   с описанием продукта, экранами, ценами и CTA, доступная без авторизации.
   Без неё сайт не ранжируется ни по одному запросу кластера 2.
2. **Посадочные под интеграции** (кластер 3) — по странице на запрос.
3. **Блог** под кластер 4.
4. **Подключить Google Search Console и Яндекс.Вебмастер**, отправить
   `https://www.markvision.kz/sitemap.xml`.
5. **Проверить, что домен один.** Превью-домен `markvision-a1.lovable.app`
   отдаёт тот же сайт — это дубль. Либо закройте его от индексации, либо
   поставьте на нём canonical на `markvision.kz`.

## Как добавить новую страницу

1. Добавить `<Route>` в `src/App.tsx`.
2. Добавить запись в `SEO_ROUTES` (`src/lib/seo.ts`). Тест не даст забыть.
3. Публичная страница — `index: true`, `priority`, при необходимости `jsonLd`.
   Раздел кабинета — используйте хелпер `appRoute(...)`, он ставит noindex.
4. `npm run build` — sitemap и robots обновятся сами.
