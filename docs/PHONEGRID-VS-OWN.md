# Свои виртуальные телефоны вместо PhoneGrid: что это даст и чего не даст

Разбор вопроса «зачем нам чужой сервис, давайте построим телефоны у себя и сложим всё
в одну платформу». Коротко: **телефоны повторить можно, но не нужно; а вот убрать второй
кабинет и свести управление в MarkVision — нужно и несложно.** Ниже почему.

## 1. Что такое PhoneGrid технически

Это не эмуляторы в привычном смысле и не физические телефоны в стойке. Это **контейнеры
с Android на серверах**: на Linux-хосте поднимается много изолированных Android-систем,
каждая со своим состоянием, приложениями и выходом в сеть.

Что они продают поверх голого Android:

| Слой | Что делает | Насколько сложно повторить |
|---|---|---|
| Контейнеры Android | много независимых устройств на одном сервере | **легко** — есть готовый Redroid |
| Стрим экрана и ввод | смотреть и тыкать в телефон из браузера | **средне** — scrcpy / WebRTC |
| API управления | создать, включить, поставить приложение, выполнить команду | **средне** — обвязка над ADB |
| Проксирование | весь трафик устройства через ваш прокси | **средне** — на уровне контейнера |
| Каталог приложений | нужные версии Instagram/TikTok под RPA | **муторно** — хранить и обновлять APK |
| RPA-движок | сценарии «полистай ленту, лайкни» на нодах | **долго** — свой конструктор |
| **Антидетект** | чтобы Instagram не понял, что это сервер | **очень сложно, это и есть их продукт** |

## 2. Про антидетект — главный пункт

Голый контейнер Android площадки вычисляют за минуты. Что их выдаёт:

- `ro.product.model` и `build.fingerprint` — у контейнера они generic, у реального телефона свои;
- нет IMEI, нет SIM, нет номера телефона;
- GPU отдаётся программным рендерером, а не чипом Adreno/Mali;
- нет датчиков: акселерометр, гироскоп, освещённость — у сервера их физически нет;
- `/proc/cpuinfo` выдаёт виртуализацию;
- Play Integrity не проходит.

Наш CP-1 в PhoneGrid отдаёт: модель `V2361GA` (реальная vivo), IMEI `862133078019136`,
номер `+7717…`, MAC Wi-Fi и Bluetooth, часовой пояс и язык под страну прокси. Всё подменено.
**Это и есть то, за что платят.** Повторить — не неделя работы, а постоянная гонка:
площадки меняют проверки, кто-то должен на это реагировать. Один человек такое не тянет
параллельно с основным продуктом.

## 3. Если всё-таки строить своё

Стек, который работает в 2026 году:

- **[Redroid](https://github.com/remote-android/redroid-doc)** — Android в Docker, образы вплоть
  до Android 16, arm64 и amd64, GPU-ускорение.
- **Сервер обязательно ARM** (Ampere, AWS Graviton, Hetzner CAX): Instagram и TikTok собраны
  под ARM, на x86 нужен слой трансляции — медленно и заметно. На ARM Android идёт нативно,
  без KVM.
- **ADB** для управления, **scrcpy** для экрана, **redsocks/iptables** для прокси на контейнер.
- Оркестрация через Docker Compose или Kubernetes.

Порядок величин: один инстанс просит примерно 2 ГБ памяти, то есть сервер на 32 ГБ тянет
десяток-полтора телефонов. Это дешевле поминутной оплаты **на объёме от нескольких десятков
устройств**, но только если не считать время на разработку и поддержку антидетекта.

Честная оценка сроков: рабочий прототип — недели, состояние «аккаунты не банят» — месяцы,
и это не разовая работа.

## 4. Про прокси: подключать его «к платформе» нечему

Прокси нужен **устройству**, а не платформе. Смысл прокси в том, чтобы Instagram видел
казахстанский мобильный IP там, где сидит аккаунт. Наша платформа публикует через официальные
API с серверов Supabase — ей прокси не нужен и не поможет: Meta и TikTok не смотрят, с какого
IP пришёл API-запрос, они смотрят на токен.

Поэтому прокси и «идёт в PhoneGrid» — он там, где живёт устройство. Если строить свои телефоны,
прокси будет точно так же подключаться к ним, просто в своей панели вместо чужой.

## 5. Главное: почему подключать аккаунт всё равно придётся

Это не недостаток PhoneGrid и не исправится своей платформой. Вход в приложение и доступ
к API — **разные вещи по устройству самих площадок**:

| | Вход в приложении на телефоне | OAuth-подключение в MarkVision |
|---|---|---|
| Что даёт | сессию внутри приложения | токен для Graph API |
| Кто выдаёт | приложение Instagram | Meta, после явного согласия владельца |
| Что позволяет | листать, лайкать, публиковать руками | публиковать программно, читать статистику |
| Можно ли получить из первого | **нет** | — |

Сессия приложения живёт на устройстве и не конвертируется в API-токен: Meta специально
разделила эти вещи, иначе любой, кто получил доступ к телефону, получал бы и доступ к API.
**Никакая платформа — ни PhoneGrid, ни наша — это обойти не может.**

Значит статистика по аккаунту берётся не с телефона, а по API, и для этого аккаунт должен быть
подключён. Одно действие, один раз за жизнь аккаунта, минута времени.

Альтернатива — снимать цифры с экрана телефона роботом. Так делают, но это медленно, ломается
от любого редизайна и даёт куда меньше данных, чем `insights`. Не наш путь.

## 6. Что действительно стоит сделать: спрятать PhoneGrid внутрь MarkVision

Второй кабинет убирается не заменой движка, а тем, что вы перестаёте в него заходить.
У PhoneGrid есть **Open API** (`api.phonegrid.com`, OAuth client_credentials) — он умеет всё,
включая RPA-расписания, и работает с сервера. Значит:

| Сейчас | Как должно быть |
|---|---|
| телефоны — в кабинете PhoneGrid | список телефонов в карточке аккаунта MarkVision |
| прокси — в кабинете PhoneGrid | прокси заводится в MarkVision и уходит в PhoneGrid по API |
| прогрев — руками в маркетплейсе | кнопка «прогреть» в карточке аккаунта, расписание ставится по API |
| статистика — в MarkVision | там же |
| подключение аккаунта — отдельно | мастер в одном окне: телефон → регистрация → прогрев → OAuth |

Единая карточка аккаунта: телефон, прокси, день прогрева, статус OAuth, здоровье токена,
охваты. PhoneGrid остаётся под капотом как поставщик устройств — так же, как Supabase остаётся
поставщиком базы, а вы про него не думаете.

**Сделано 06.09.2026:** в карточке аккаунта появился раздел «Устройство и прогрев» —
привязка телефона, включение и выключение, полоса прогрева по дням и история запусков.
Движок — PhoneGrid Open API (edge-функция `account-devices`, клиент `_lib/phonegrid.ts`),
кабинет PhoneGrid для ежедневной работы больше не нужен.

**Это реально сделать за обозримое время**, в отличие от своего антидетекта. И если однажды
захочется съехать с PhoneGrid на свои Redroid-телефоны — интерфейс и логика уже будут свои,
поменяется только драйвер устройств. Правильный порядок: сначала обёртка, потом (может быть)
свой движок.

## 7. Вывод

1. **Свои телефоны — можно, но не сейчас.** Технология доступна, но ценность PhoneGrid
   не в контейнерах, а в антидетекте, который придётся поддерживать вечно.
2. **Прокси там, где устройство.** Платформе прокси не нужен.
3. **Двойное подключение неустранимо** — так устроены Meta и TikTok. Но это одна минута
   один раз на аккаунт.
4. **Единая платформа достигается обёрткой**, а не заменой движка: PhoneGrid Open API
   заводится внутрь MarkVision, и второй кабинет исчезает из вашей работы.
