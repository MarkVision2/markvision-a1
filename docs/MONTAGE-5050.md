# Монтаж 50/50 (split-screen)

Спикер в одной половине кадра, вторая половина — **запись экрана** (второе видео)
или **Remotion-сцена** из библиотеки (`docs/motion-library.md`). Открывается только
в важных моментах показа; вне них спикер на весь экран. Всё анимируется в Remotion.

## Как заказывается (сайт)
Контент-завод → Видео → «Монтаж съёмки» → блок **«Режим монтажа» → Монтаж 50/50** →
загрузить **два** видео: говорящую голову и запись экрана. Заявка ложится в `montage_jobs`
с `mode='5050'`, `source2_url` = запись экрана.

## Как разбирается (очередь / Claude-сессия)
1. `montage-worker.mjs next` качает оба исходника: `work/<id>/source_raw.*` (спикер) и
   `work/<id>/screen_raw.*` (экран).
2. Прокси в `remotion/public/`:
   - спикер → `source_<jobId8>.mp4` (all-intra H.264, при HEVC — обязательно; мьют по brief);
   - экран → `screen_<jobId8>.mp4` (то же; если 4K/60 — ужать до 1080/30).
3. Анализ спикера: `transcribe.py` → `words.json` (+ `faces.py` при необходимости).
4. Разметка **сплит-моментов** — Claude по транскрипту находит, где автор **что-то
   показывает** («смотрите», «вот», «покажу», демо, называет цифры/факты) и пишет
   `work/<id>/splits.json` (см. шапку `pipeline/split.py`): для каждого момента — либо
   `screenFrom` (кусок записи экрана), либо `template`+`data` (моушн-сцена из базы по смыслу).
5. `split.py work/<id> remotion/props source_<jobId8> [screen_<jobId8>]` → `props/Split-*.json`.
6. Рендер: `npx remotion render src/index.ts Split5050 ../out/<id>.mp4 --props=props/Split-*.json …`.
7. `montage-worker.mjs complete <jobId> --video out/<id>.mp4 …` — заливка и публикация как обычно.

## Композиция
`remotion/src/Split5050.tsx` — пропсы `SplitProps`:
- `speaker`: `bottom` (default) / `top`;
- `screen`: базовое имя записи экрана в public (или `null` → моушн-сцена/плейсхолдер);
- `splits[]`: `{from,to, screenFrom? | template?+data?}` — окна показа;
- титры на стыке половин, слайд-переход, акцентная линия.

Вне сплит-окон спикер на весь экран (лицо биасом objectPosition). Мьют «паразитов»/
геометок — через прокси из подготовленного (заглушённого) исходника, как в обычном маршруте.
