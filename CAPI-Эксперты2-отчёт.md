## Карта этапов (crm_stage_map, проект Виталя)

| Этап воронки | Событие Meta |

Diagnostic — кастомное событие, Meta примет его без предварительного создания. Чтобы оптимизировать
кампании на него, в Events Manager создать Custom Conversion на Diagnostic.

## Проверка

- Прямой POST в Graph API с токеном и test-кодом → HTTP 200, `events_received: 1`, без ошибок.
  Независимая проверка «токен + пиксель рабочие».
- Сквозной прогон через CRM: создал тестового лида в проекте «Виталя» с привязкой к кабинету,
  провёл new → scheduled → visit → paid. Все четыре события ушли автоматически и получили статус
  `sent`, `events_received: 1` каждое: Lead, Schedule, Diagnostic, Purchase (value 150). Тестовые
  данные (лид, очередь, история) после проверки удалены.
- Backend живой: cron `capi-outbox-worker-minutely` активен, запуск каждую минуту.

## Как устроен воркер (важно знать)

- Токен и пиксель воркер берёт по `cabinet_id` лида. Поэтому у лида должен быть проставлен
  `cabinet_id` кабинета — иначе событие не найдёт пиксель. В боевом потоке это делает привязка
  лида к кабинету при создании.
- Воркер цепляет `capi_test_event_code` кабинета ко **всем** событиям. Пока код стоял, всё уходило
  в Test Events и не считалось реальными конверсиями. После приёмки код снят — теперь события
  идут в продакшн и считаются как конверсии.

## Для оптимизации
